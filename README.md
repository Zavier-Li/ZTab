# ZTab

本地运行的 BP 英语辩论赛管理工具，支持队伍、裁判、场地管理，对阵编排、成绩录入和积分排名。比赛数据保存在当前浏览器的 IndexedDB 中，无需业务服务器或账号。

技术栈：Vite、React、TypeScript、Tailwind CSS、基于 Radix 的 UI 组件、Dexie / IndexedDB。支持中英切换与纯白 / 纯黑主题；中文使用华文中宋，英文使用 Times New Roman，电脑未安装时使用系统衬线字体。

## 启动

### Windows 一键启动

安装 Node.js 22.12 或更高版本后，双击项目根目录的 **`启动ZTab.bat`**。脚本会在首次运行时安装依赖、构建网页，在后台启动本地服务，并使用默认浏览器打开 <http://127.0.0.1:5173>。首次安装需要联网，请等待构建完成。

以后每次双击同一个文件，都会重新构建当前源码并重启本项目的本地服务，确保启动到最新版本。关闭网页不会停止后台服务；电脑重启后再次双击即可。请保留完整项目文件夹，也可以给这个 BAT 创建桌面快捷方式。

启动失败时会弹窗提示，日志保存在 `output/launcher/`。如果 5173 端口被其他程序占用，脚本会提示处理，不会换端口或终止其他程序。

### 命令行启动

安装 Node.js 22.12 或更高版本，然后执行：

```bash
git clone https://github.com/Zavier-Li/ZTab.git
cd ZTab
npm ci
npm run dev -- --port 5173 --strictPort
```

打开 <http://127.0.0.1:5173>。

日常使用时在项目目录运行最后一条命令即可，终端保持打开。开发服务器只监听本机。

构建和本地预览：

```bash
npm run build
npm run preview -- --port 5173 --strictPort
```

预览前先停止占用 5173 端口的开发服务器。构建产物位于 `dist/`，可交给静态 HTTP 服务托管。

**请固定浏览器和访问地址。** `localhost`、`127.0.0.1`、不同端口、不同浏览器和隐私窗口的数据相互独立。清除站点数据会删除本地赛事；换电脑或换浏览器前，先导出 JSON 备份。

## 比赛现场操作

1. 打开赛事总览，选择当前赛事；其他比赛可在总览顶栏新建。
2. 在“参赛队伍”“裁判管理”“场地管理”中核对或导入资料。修改资料后按相应表单按钮保存。
3. 开场前进入“对阵编排”，选择“分层随机预排”，设置回避方式，生成并校验四轮对阵。每次自动生成新的随机种子。
4. 核对每轮场地、时间、辩位与裁判组，按需导出 PDF、PNG 或完整 ZIP。
5. 在“成绩录入”中选择轮次，逐场输入名次。队伍和人员默认折叠，点击场地名称展开或收起；展开后四队横向排列。
6. 在“积分与排名”查看队伍及辩手排名；每轮结束后备份赛事。

所有已编排轮次的正式成绩完整后，总览显示“完赛”，可直接查看排名。

### 重置赛事

赛事设置顶栏点击“重置赛事”，勾选要清空的项目，再点击“确认重置”。可分别选择成绩与评分、赛程与对阵、队伍与辩手、裁判资料、场地资料、赛事设置与安排；默认只勾选成绩与评分。

清空赛程也会清空其全部评分；清空队伍或场地会联动清空赛程和评分，弹窗中会自动勾选。清空裁判会删除裁判安排及个人评分；若未勾选清空成绩，正式成绩保留。清空场地还会移除场次安排。

其他赛事、当前赛事名称保持不变。此操作无法撤销，执行前请导出 JSON 备份；取消则不修改数据。

### CUDC 预设

首次启动内置“2026 CUDC 西安电子科技大学校选赛”，包含 12 支队伍、24 名辩手、8 名裁判和 C107、C110、C128 三个场地，以及四轮时间和裁判安排。**预设不包含已生成对阵或比赛成绩**，供开场现场随机排阵。

也可以在“数据中心”导入 [CUDC 赛前配置](赛事文件/CUDC-赛前配置.json)，创建独立赛事。内置资料包含参赛名单，联系方式和学号不在配置中；如用于其他比赛，请新建赛事并导入自己的名单。

## 对阵编排

### 分层随机预排

- 支持至少 4 支启用队伍，队伍数须为 4 的倍数；每轮每场 4 队。需要足够的启用场地，不再自动创建固定场地。
- 一次编排四轮，每队每轮上场一次，OG、OO、CG、CO 各一次。场地多于每轮所需数量时，可参与轮换；已有明确场地裁判计划时优先遵循计划。
- 点击“强队标签”打开队伍及两名选手列表，点击队伍标记，再次点击取消。标签自动持久化，已选队伍显示在编排浮窗中；只对启用队伍分层，零个或全部标记相当于不分层。
- 分层时每轮各场强队数量最多相差一支；在强队组和非强队组内，优先缩小四轮累计遇强次数差距，再优化不同对手覆盖与重复交手。
- 不按固定强队数量限制；例如 12 队标记 4 队时，每轮分布为 2、1、1。标签不预设晋级资格，不能用缺乏依据的主观评价代替赛前约定。
- 严格同校回避和强队分布是排阵约束；重复交手没有硬上限，会作为优化指标减少。
- 优先避免单对交手超过两次，再增加不同对手并均衡分布；这只是优化目标，不是可配置的硬上限。12 队、四轮、每轮三场时，已验证的基准为 54 个不同队对、每队 9 个不同对手、单对最多交手两次。强队标签纳入均衡目标；10 秒内找到并满足优先目标时标记已验证，否则返回当前最佳近似方案。
- 资源分配在三个及以下场地且没有额外场地时穷举；较多场地使用交换搜索，均衡场地及裁判接触。有限搜索结果不会宣称所有公平因素同时全局最优。
- 可设置同校回避方式和搜索强度；每次排阵自动生成新种子并存入备份。搜索预算为 10 秒，超时返回已找到的最佳可行排阵。
- 同校队伍回避与提醒在至少三所学校时启用；裁判回避独立检查。

无任何正式成绩、裁判评分或评分草稿时，可以重新生成四轮；已有录入后禁止重排。生成后也可在允许编辑的赛场调整队伍、场地及裁判，系统会校验冲突和辩位约束。

### 成绩配对

在对阵编排选择 **BP Power Match**。首轮随机，之后按累计队伍积分分池；池人数不满四的倍数时，从相邻低分池升池，升池队伍可以进入整个上池。不会按辩手分将总榜机械地每四队切一场。

升池选择优先照顾此前升池次数较少的队伍，再以随机打乱的匈牙利匹配优化辩位分布（Shannon 熵成本、四次方惩罚）。在同等主目标的候选中减少重复交手和同校同场；不以牺牲积分池或升池公平为代价。位置冲突时可重复辩位并显示提醒，不能保证四轮四辩位各一次，也不会为凑齐辩位任意跨越积分池。

页面及JSON备份记录随机种子、积分池、升池、位置成本和重复交手。预赛默认四轮，可在赛事设置修改预赛轮数。前序正式成绩须完整且没有待确认的正式草稿，才可生成下一轮；生成后先前成绩锁定。全部计划轮次完成后显示“完赛”。

规则依据：[Tabbycat BP 编排说明](https://tabbycat.readthedocs.io/en/stable/features/draw-generation-bp.html)。此处实现BP积分池、升池和辩位匹配机制，不代表整个赛事已获WUDC全部条款合规认证。原有赛程与成绩不会自动替换；切换策略应新建赛事或先重置赛程。

## 成绩录入

### 快捷名次

按 **OG → OO → CG → CO** 输入四位名次，例如 `4132`：

| 辩位 | 名次 | 队伍积分 |
| --- | --- | --- |
| OG | 第 4 名 | 0 |
| OO | 第 1 名 | 3 |
| CG | 第 3 名 | 1 |
| CO | 第 2 名 | 2 |

- 首次填入有效的四位名次后自动保存，无需 Enter 或保存按钮。
- 已保存时，快捷输入框显示实际名次；待录入时显示“例：4132”。
- 已有完整成绩后修改名次，会保留原正式成绩。按 **Enter** 弹出确认框，确认后覆盖；取消则原成绩不变。点击框外再聚焦修改同样遵循此规则。
- 不完整或无效输入保存为草稿，不计入排名；草稿可在刷新后恢复。
- 展开赛场也可用下拉框逐队选择名次，名次必须为 1、2、3、4 各一次。
- 辩手分数可留空，填写时范围为 60–100；输入自动保存。留空分数不计入辩手均分。

### 评分记录与正式成绩

默认录入“本场正式成绩”，只有正式成绩计入排名。若需要保留各裁判评分，可在“评分记录”选择本场裁判单独填写，再通过“确认为正式成绩”采用该份记录。裁判记录不会自动平均或自动替代正式成绩。

“逐场完整结果”可查看所有轮次、赛场、队伍、正式名次、队伍积分和辩手分数。队伍排名按积分、辩手总分、队名排序。

## 导入与导出

### 表格导入

队伍、裁判、场地页面支持 Excel / CSV，使用首个工作表，识别常见中英文表头。建议先用小表核对导入结果。

| 数据 | 常用表头 |
| --- | --- |
| 队伍 | 队名、学校、辩手1、辩手2 |
| 裁判 | 姓名、学校、等级、工作任务、工作时间 |
| 场地 | 场地 |
| 成绩 | 轮次、场地、队名、裁判、辩手1分数、辩手2分数、名次 |

成绩页面可下载当前轮评分模板。裁判列留空表示正式成绩，填写裁判姓名表示该裁判的评分记录。每组必须包含该场四队且名次不重复；无效文件会报错，避免部分导入。

对阵页面支持导入本轮对阵；引用的队伍、场地和裁判应先存在于赛事中。数据中心支持 ZTab JSON、排程 JSON 和旧版 `tournament.db` 导入，导入会创建独立赛事。

### 导出及备份

- **PDF / PNG**：对阵、逐场结果、队伍排名与辩手排名，可从相应页面顶栏导出。
- **CSV**：排名及对阵等表格数据，使用 UTF-8 BOM，便于 Excel 打开。
- **完整 ZIP**：四轮随机排程的 PNG、Excel 和排程 JSON。
- **其他格式**：对阵页还提供演示与打印相关导出。
- **JSON 备份**：保存队伍、裁判、场地、对阵、正式成绩、裁判评分和草稿。使用总览顶栏“备份赛事”或数据中心“导出完整 JSON 备份”。恢复时在数据中心导入。

PDF、PNG、CSV 用于展示或汇总；换设备继续比赛请使用完整 JSON 备份。

## 开发与检查

```bash
npm test
npm run build
```

测试覆盖随机数一致性与预排覆盖上界、辩位和交手约束、裁判分配、导入校验、CUDC 配置、IndexedDB 持久化与成绩自动保存。

主要目录：`src/pages/` 为页面，`src/lib/` 为编排、成绩、存储和导入导出逻辑，`src/data/` 为内置配置，`赛事文件/` 为可导入的赛前备份。搜索算法在 Web Worker 中运行。
