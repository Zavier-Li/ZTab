# ZTab 重写范围与验证计划

在当前目录独立重写，原 Python、SQLite、Excel 不修改。Vite + React + TypeScript + Tailwind CSS + shadcn/ui（Radix Dialog/Slot、CVA）；Dexie 保存多赛事项目，赛事服务与算法均运行于浏览器，不依赖业务服务器。

1. 数据：队伍、两名辩手、学校、二语、启用；裁判等级、工作轮次/时间、学校与队伍回避；场地；轮次、对阵、成绩。历史实体仅停用。项目分开存储，导入原 SQLite 或 JSON 创建新项目。
2. BP Power Match：首轮随机，后续按累计队伍积分池编排，允许升池进入整个上池；升池历史优先于 Shannon 熵辩位成本，以随机打乱的匈牙利匹配求主目标最小，在等价主目标候选中减少重复交手。重复辩位可提醒，不作为 BP 非法赛程。预赛默认四轮可配置，已有预设裁判计划时保持场地与裁判计划。
3. 四轮随机：每队四种辩位各一次，重复交手无硬上限；优先避免单对交手超过两次，再优化对手覆盖与强队均衡。12 队基准为 54 个不同队对、每队 9 个不同对手、单对最多交手两次。Worker 在固定 10 秒预算内搜索目标与同校回避，满足并命中基准时标记已验证，否则返回并标注预算内最佳可行排阵。每次生成自动随机种子并写入赛事元数据。
4. 导入导出：Excel/CSV 中英文表头、学校向下填充、首轮对阵导入、旧 SQLite 导入；JSON 备份/还原、排名和对阵 CSV、HTML overview/ballot、PPTX；随机模式 ZIP 包含四张 PNG、四场对阵 Excel 和校验 JSON。
5. 界面：浅色工作台，侧栏导航，赛事总览、参赛队伍、裁判管理、场地、对阵、成绩、队伍/辩手排名、数据中心、设置。显式示例项目；不内嵌报名表联系方式。
6. 验证：算法约束与默认种子 Python 对照、非法成绩/导入校验、历史数据与 IndexedDB 持久化；生产构建；浏览器完整流程与窄屏检查；生产静态资源离线检查。

最优认证仅限已证明的对手覆盖目标，以及固定分组及计划下穷举的资源分配。次级分组优化是有限搜索。BP机制参考Tabbycat的积分池、升池和辩位算法；不宣称整个赛事获WUDC全条款认证。历史赛事仍可读取；新预排与BP不复现旧Python的特定队伍调整。
